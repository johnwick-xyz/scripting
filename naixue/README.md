# 奈雪点单小程序每日签到（Loon 插件）

参考樱花佬 Sliverkiss 的 `naixue.js`（奈雪点单签到，2024.04.26）：
域名是 `tm-web.pin-dao.cn`，打开小程序 → 我的 → 签到页面，抓 Cookie（ck），每天 9:00 重放签到。
Sliverkiss 原脚本是混淆的，这里不用它的代码，只按它的思路做抓取重放：
装好插件后手动签到一次，把签到请求原样存下来，第二天开始定时重放。

## 文件

| 文件 | 作用 |
|---|---|
| `Naixue.lpx` | Loon 插件：MITM `tm-web.pin-dao.cn`，装抓取脚本 + 每天 9:00 的签到定时 |
| `NaixueGetAuth.js` | 抓取脚本：存 Cookie / Token，存签到 POST 请求整个（URL+头+体） |
| `NaixueSign.js` | 定时脚本：每天 9:00 重放抓到的签到请求，Cookie 换成最新的 |

## 抓一次（必须）

1. 打开微信 → 奈雪点单小程序 → 点「我的」→ 进签到页面，手动签到一次。
2. 抓取脚本会弹通知：
   - 「奈雪 Cookie 已抓取」——凭证有了；
   - 「奈雪签到请求已记录」——签到请求有了，明天 9:00 自动签。
3. 两个通知都收到才算抓完。只收到 Cookie 没收到签到请求，说明那次没点到签到按钮，再进签到页点一次。

## 注意

- **抓到之后别再打开小程序**。按 Sliverkiss 的说法，打开小程序会让 ck 失效；ck 失效了自动签到会失败，需要重新手动签一次再抓。
- 凭证只存在 Loon 本地（`$persistentStore`），不上传、不进 GitHub。
- 如果自动签到失败，先看通知里的报错；再手动签一次重新抓（请求可能换了）。
- 如果一次抓取通知都没弹，打开 Loon 的请求记录，看小程序实际走了哪个域名，再把那个域名加进插件的 MITM 和抓取规则里。

## 和霸王茶姬的区别

霸王茶姬（CHAGEE）那个要每天现算 MD5 签名，不能直接重放，所以是现算签名的脚本。
奈雪这个按 Sliverkiss 的做法就是 Cookie 重放，不用算签名，简单很多——代价是 ck 失效就要重新抓。
